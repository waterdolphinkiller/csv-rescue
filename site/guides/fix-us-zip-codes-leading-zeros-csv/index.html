How to Fix Excel Stripping Leading Zeros from US ZIP Codes (02138, 07030) Offline

Direct Answer: Excel strips leading zeros from US ZIP codes (like 02138 in Massachusetts or 07030 in New Jersey) because it auto-casts raw CSV fields into integers on double-click. To repair them without uploading customer addresses, load the file into CSV Rescue locally, run Preserve Leading Zeros (5-digit or ZIP+4 text padding), and export as Excel SpreadsheetML (.xls) or UTF-8 BOM CSV.

The Boston 02138 Shipping Label Failure

A Northeast fulfillment coordinator exports 4,200 Shopify orders on Monday morning, opens the CSV in Excel to check one column, and hits Save. Ten minutes later, UPS WorldShip and ShipStation reject 680 Massachusetts, Connecticut, New Jersey, Maine, and Puerto Rico shipments with "Invalid Postal Code."

Excel did not throw a single warning. It quietly converted "02138" into 2138, "07030" into 7030, and "02108-1234" into mangled strings. If you are dealing with real customer home addresses, uploading that file to a random web-based CSV fixer creates an unnecessary PII leak.

Frequently Asked Questions

Why does Excel delete the zero at the start of New England and New Jersey ZIP codes?

CSV is plain text with no column type metadata. When Excel opens a CSV via double-click, its General formatter parses digits as integers, silently discarding leading zeros.

Does CSV Rescue preserve ZIP+4 codes like 02108-1234?

Yes. CSV Rescue detects both 5-digit ZIP codes and ZIP+4 patterns (e.g., 2108-1234 → 02108-1234) without stripping the hyphen or suffix.

How do I stop Excel from breaking the ZIP codes again after I repair them?

Export using CSV Rescue’s Excel SpreadsheetML (.xls) preset, which writes explicit String cell types so Excel opens 02138 as text, or import the UTF-8 CSV via Excel Data → From Text/CSV with the column set to Text.
